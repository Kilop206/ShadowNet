# Milestone 5 — Production Security

Versão 0.5.0. Mantido o protocolo WSS v3 e o fluxo HTTPS → Gateway → Agent →
loopback. O M5 acrescenta políticas HTTP independentes, gestão administrativa
de confiança/rotação, CRL local opcional, revalidação em sessões estabelecidas,
checagem de chaves no Windows/Unix e proteção contra amplificação de logs.

- Métodos e prefixos por segmento são conferidos por ambos os lados. O default
  aceita sete métodos usuais em `/`; extensões precisam de autorização explícita.
  Queries não são ACLs. Paths ambíguos são rejeitados antes da origem.
- CRLs configuradas não têm fallback silencioso: OpenSSL valida revogação da
  cadeia. Cada sessão WSS revalida cadeia peer/identidade/propósito/validade e
  leaf local a cada segundo. CRL/certificado expirado encerra sessão ativa.
- `certificate_sha256_next` permite rotação com sobreposição para a mesma
  identidade, sem adicionar uma segunda sessão. Aplicar/remover pins e CRLs
  exige reinício controlado; não há hot reload automático.
- Chaves têm limite de 64 KiB, precisam ser regulares, sem symlink final e com
  um hard link. Windows inspeciona owner/DACL com APIs do SO; Unix exige
  permissões restritas. O runtime não corrige silenciosamente permissões.
- Logs não incluem dados HTTP sensíveis e limitam emissão a 200 eventos/s,
  burst 400, com contador de supressão. Não são trilha de acesso completa.
- Sem nova dependência de terceiros. `advapi32` é biblioteca do Windows;
  validação X.509/CRL continua no OpenSSL, sem criptografia própria.

O [guia de segurança](../security/production.md) contém exemplos, procedimentos
de rotação, matriz de revisão interna e riscos residuais; o [modelo de ameaças](../security/threat-model.md)
define as fronteiras. A revisão é interna, não auditoria independente.

## Comandos e resultados locais

Windows x64, GCC/MinGW-w64 16.2.0, CMake 4.4.3, OpenSSL 4.0.3 e LLVM 23.1.3.

```powershell
cmake --preset bootstrap -G 'MinGW Makefiles' -B build/mingw -DOPENSSL_ROOT_DIR=C:/openssl-4.0.3/x64
cmake --build build/mingw --parallel 3
ctest --test-dir build/mingw -V
ctest --test-dir build/mingw -R e2e.security -V
./scripts/check-static.ps1 -BuildDir build/mingw
cmake --install build/mingw --prefix build/install
./build/install/bin/shadow.exe version
./build/install/bin/shadow.exe config validate --type agent --config build/dev-pki-m5-final/agent.wss.yaml
./build/install/bin/shadow.exe config validate --type gateway --config build/dev-pki-m5-final/gateway.wss.yaml
```

- **6/6 suítes CTest aprovadas** na execução integral final, incluindo
  **16 cenários de segurança**.
- **8289 assertions em 19 casos Catch2**, incluindo política, corpus de
  **5000 mutações determinísticas** e flood de **5000 eventos de log**.
- Regressões M1: 10 aprovados + 1 SIGTERM POSIX ignorado no Windows.
- Regressões M2/v3: 21 aprovados + 1 SIGTERM POSIX ignorado no Windows.
- M3: **26 cenários HTTP E2E aprovados**; M4: **9 cenários aprovados**.
- Carga de regressão de 5,012 s/12 workers: **2707 respostas corretas**, 19
  falhas transitórias nas janelas de duas reinicializações, zero erros
  inesperados e zero POST duplicado na origem. Não é benchmark de produção.
- M5: Gateway e Agent negam políticas independentemente; traversal/encoding,
  regras/pins inválidos, rotação, CRL válida/revogada nos dois sentidos,
  expirada/malformada/ausente/estrangeira e assinatura adulterada. Testados
  expiração ativa de certificado/CRL, hard links e DACL com Everyone. Symlink
  de chave é testado em Unix, sem habilitar privilégios extras no Windows.
- A revisão reproduziu, antes da publicação, uma ampliação indevida de confiança
  ao usar carregador genérico de PEM para CRL. Foi trocado por carregador somente
  de CRLs. O teste forja um Gateway e mistura sua CA no bundle, verificando que
  essa CA não passa a ser confiável. A correção foi seguida de nova execução integral.
- clang-tidy: **19 unidades de produção analisadas**; a advertência de par de
  parâmetros HTTP foi suprimida localmente com justificativa e a unidade foi
  reanalisada sem diagnóstico. Há também a supressão existente dos flags de
  verificação OpenSSL. Avisos de dependências não equivalem a auditoria delas.
- Instalação local, `ShadowNet 0.5.0` e validação offline das duas configurações
  passaram. Certificados/CRLs/chaves de teste não são versionados.

A sandbox Windows bloqueou WRITE_DAC; geração de novas chaves/fixtures e testes
foram executados sob a conta autorizada, com a DACL restrita mantida. Não houve
relaxamento do verificador para aprovar o ambiente de teste.

## Linux/Docker executado

```powershell
python scripts/dev-certificates.py --output build/dev-pki-m5-final
$env:SHADOW_PKI_DIR='../build/dev-pki-m5-final'
docker compose -p shadownet-m5 -f docker/compose.yaml up --build -d
python scripts/check-demo.py --ca-file build/dev-pki-m5-final/ca.crt
docker compose -p shadownet-m5 -f docker/compose.yaml restart gateway
python scripts/check-demo.py --ca-file build/dev-pki-m5-final/ca.crt
docker compose -p shadownet-m5 -f docker/compose.yaml down
```

O daemon inicialmente estava desligado; Docker Desktop foi iniciado para a
validação. A imagem Linux foi compilada. **16 requisições HTTPS** aos dois
serviços passaram antes e outras **16 após reinício do Gateway**, concorrência
8, com CA/SAN/SNI verificados. Os quatro contêineres encerraram com código 0;
contêineres e rede do laboratório foram removidos. A CA privada não foi montada.
O gerador recusa sobrescrever uma PKI; usar diretório novo e não instalar a CA.

## Limitações e próximo passo

CRL local é opt-in, carregada no início; sem CRL, revogação depende da remoção
administrativa do pin/reinício. Não há OCSP, download de CRL, hot reload,
rotação automática, cofre de segredos ou auditoria externa. O ciclo descrito
tem interrupção de conexões. Checagens periódicas dependem de relógio/agendamento.

Proteger diretórios pais e a conta do processo continua obrigatório: checagem
de permissões e abertura OpenSSL por caminho não são snapshot atômico contra
adversário local privilegiado. DACLs complexas podem falhar conservadoramente.
Logging pode suprimir eventos e não tem persistência/assinatura/rotação internas.

ACL de método/path não autentica visitantes nem controla rewrites da aplicação.
Percent-encoding reservado/Unicode no path e formatos ambíguos podem exigir
adaptação de aplicações. HTTP continua sem streaming e com corpo até 1 MiB.
Não há validação física de NAT/CGNAT ou carga distribuída de produção. LAN,
ISP e operadores observam dispositivo/tráfego; conteúdo da aplicação pode
revelar o IP da origem. Não há promessa de invisibilidade.

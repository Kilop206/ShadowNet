# Milestone 6 — Observability

Versão 0.6.0, sem mudança do protocolo WSS v3. Critério: medir conexões,
latência, throughput, requisições, erros e estado dos agentes, exportar para
Prometheus e demonstrar integração opcional Grafana. Não acrescenta dashboard
administrativo nem comandos CLI de status fictícios.

Registro tipado e thread-safe sem dependência C++ adicional. Contadores por
processo, histograma cumulativo de segundos e observações RAII encerradas uma
vez. Labels fixas e identidades somente da configuração limitam cardinalidade;
dados HTTP sensíveis não viram séries. HTTP no Gateway e no Agent têm pontos
de conclusão diferentes, documentados no [guia operacional](../observability.md).

Exporter opt-in somente loopback; portas públicas/serviços não podem coincidir.
GET/HEAD, Host local, sem Origin/corpo, headers/buffer/resposta/conexões/prazo
limitados. Scrapes não inflam RPS da aplicação. Reconexões mantêm o registro do
Agent; término sem reconnect fecha o exporter, permitindo encerrar o event loop.

O overlay executa Prometheus/Grafana externos com imagens fixadas por digest,
senha descartável gerada e restrita, auth obrigatória no Grafana e histórico em
tmpfs. Coleta apenas Gateway; estado dos agentes vem da tabela de identidades.
Sidecar compartilha namespace para preservar bind local do exporter.

## Build e testes executados

Windows x64, GCC/MinGW-w64 16.2, CMake 4.4.3, OpenSSL 4.0.3 e LLVM 23.1.3.
Build já configurado com dependências bootstrap fixadas; comandos:

```powershell
cmake --preset bootstrap -G 'MinGW Makefiles' -B build/mingw
cmake --build build/mingw --parallel 3
ctest --test-dir build/mingw -V
./scripts/check-static.ps1 -BuildDir build/mingw
cmake --install build/mingw --prefix build/install-m6
./build/install-m6/bin/shadow.exe version
```

No Linux: `cmake --preset bootstrap`, `cmake --build --preset bootstrap`,
`ctest --preset bootstrap`. Windows exige runtime MinGW/OpenSSL no PATH;
se necessário, fornecer `OPENSSL_ROOT_DIR` ao configurar.

- Build nativo e instalação executados; versão `ShadowNet 0.6.0`.
- **7/7 conjuntos CTest passaram**, 62,04 s na execução integral revisada.
  Catch2: **8474 assertions em 24 casos**. Integração TCP: 11 testes;
  TLS/WSS: 22; HTTP: 26; confiabilidade: 9; segurança: 16; métricas: 10.
- Dois testes SIGTERM são explicitamente pulados no Windows, pois
  `process.terminate` não entrega sinal POSIX. Os demais passaram.
- M6 comprova contagens/bytes/status, privacidade, exclusão de scrapes, HEAD,
  24 POSTs com concorrência, buckets cumulativos, reservas/gauges balanceados,
  timeout/CANCEL/upload incompleto, reconexão, identidade duplicada, limites,
  schema e rejeição de Host/Origin. Quatro casos unitários incluem quatro
  threads e cardinalidade máxima de 1024 nomes.
- Snapshot E2E preserva LF com escrita binária no Windows. Após esse ajuste,
  o conjunto M6 foi repetido: **10/10**, 6,81 s. A fixture de peer fecha sockets
  também se handshake falhar; execução revisada sem ResourceWarning.
- clang-tidy analisou **21 unidades de produção**. Três diagnósticos foram
  corrigidos com resultados tipados e reserva do vetor; as duas unidades
  alteradas foram reanalisadas sem diagnóstico do projeto. Supressões OpenSSL/
  parâmetros HTTP herdadas do M5 permanecem localizadas e justificadas.
- Validação offline dos dois YAML gerados com métricas passou.

Geração de chaves/fixtures requer WRITE_DAC no Windows. CTest foi executado
sob a conta autorizada para manter DACLs restritas; não houve relaxamento de
permissões no runtime. Logs e PKIs ficaram em `build/`, ignorado pelo Git.

## Docker e integração executados

O [guia](../observability.md) contém os comandos completos. Foram executados
geração com `--metrics`, build da imagem Linux e inicialização dos seis
contêineres (Gateway/Agent/API/website/Prometheus/Grafana).

- `check-demo.py`: **16 requisições HTTPS** em dois serviços, concorrência 8,
  com CA/SAN/SNI verificados; outras **16 após reiniciar Gateway** passaram.
- `check-monitoring.py`: ingestão real, oito painéis provisionados, datasource
  saudável e bloqueio de acesso anônimo confirmados antes e após recuperação.
- `promtool check config`: configuração válida.
- `promtool check metrics`: snapshot real do E2E aceito, sem erro de formato
  ou lint. Foi lido por bind mount, preservando LF; um primeiro pipeline
  PowerShell adicionou CRLF e foi corrigido no procedimento e no artefato.
- A validação descobriu CRLF no arquivo de senha gerado no Windows; o gerador
  passou a gravar bytes ASCII sem quebra. Grafana reiniciado autenticou com a
  mesma senha pretendida. O checker não segue redirects nem repete 401/403.
- Reiniciar somente Gateway preservou o proxy/reconexão, mas interrompeu acesso
  ao Prometheus no namespace antigo. Reiniciar também o sidecar restaurou coleta
  e datasource. Esse requisito operacional está documentado, sem alegar
  recuperação automática do monitoramento.
- Os seis contêineres encerraram com código 0; contêineres e rede do projeto
  de laboratório foram removidos. A PKI privada não foi versionada.

## Limitações e próximo milestone

Loopback não autentica processos locais. Não há tracing, RSS/CPU, métricas por
visitante/serviço, alertas prontos ou retenção interna. Bytes de payload e
reservas não medem tráfego da interface ou RSS. Conclusão de escrita/fila não
prova leitura pelo usuário. Identidade conectada não prova saúde do backend.

O overlay é laboratório sem histórico durável, sem coleta remota do Agent;
produção exige monitoramento administrado e atualizações próprias. Segurança
do túnel não torna a origem invisível na LAN/ISP e não impede vazamento por
conteúdo/DNS da aplicação. Não houve benchmark WAN/NAT/CGNAT em redes físicas.

Resumo para commits:

- `feat: expose bounded operational metrics through local Prometheus endpoints`
- `docs: document milestone 6 metrics and monitoring operations`

local demonstrável. O repositório começou vazio. Nenhuma funcionalidade de
túnel público, TLS ou proxy HTTP é declarada entregue neste milestone.

## Decisões

- C++20, bibliotecas estáticas modulares e core de interfaces pequeno.
- Boost.Asio para I/O assíncrono e deadline total; buffers privados por sessão.
- yaml-cpp 0.9.0, Boost 1.90.0 e Catch2 3.8.1 no bootstrap, com SHA-256.
- Atualização para yaml-cpp 0.9.0 após falha real do 0.8.0 por include ausente
  com GCC 16; nenhuma alteração nas fontes das dependências.
- Listener e destinos limitados a loopback literal enquanto não há TLS.
- Frame versionado validado antes de alocar, teto de sessões e fechamento
  idempotente. Nenhuma autenticação é inferida do nome enviado pelo Agent.
- CLI inicia processos em primeiro plano e valida configuração; comandos
  ainda não implementados falham com código 2.
- Compose M1 compartilha namespace de rede para permitir loopback, sem portas
  publicadas. O exemplo de API não é encaminhado pelo túnel.

## Comandos executados e resultados locais

Ambiente: Windows x64, GCC/MinGW-w64 UCRT 16.2.0, CMake 4.4.3, Python 3.14.3.

```powershell
python scripts/fetch-deps.py --direct
cmake --preset bootstrap -G 'MinGW Makefiles' -B build/mingw
cmake --build build/mingw --parallel 4
ctest --test-dir build/mingw --output-on-failure
ctest --test-dir build/mingw -V
./scripts/check-static.ps1 -BuildDir build/mingw -MingwRoot C:/mingw64
cmake --install build/mingw --prefix build/install
./build/install/bin/shadow.exe version
./build/install/bin/shadow.exe config validate --type gateway --config build/install/share/shadownet/config/gateway.local.yaml
docker compose -f docker/compose.yaml config --quiet
```

- Build: os três executáveis e o runner de testes compilados com sucesso.
- CTest: **2/2 suítes aprovadas**.
- Catch2: **8 casos, 124 assertions aprovadas**.
- Integração: **10 cenários aprovados; 1 ignorado** explicitamente no Windows
  (SIGTERM POSIX). Inclui 16 processos Agent simultâneos e isolamento de ACKs,
  fragmentação, erro de versão/tipo/reservados, payload inválido/grande demais,
  desconexão, timeout, teto de conexões e recuperação do listener.
- clang-tidy LLVM 23.1.3: nove unidades C++ de produção analisadas com os
  includes MinGW explicitados; **nenhum diagnóstico no código de produção**
  após ajustes. Diagnósticos de bibliotecas externas são filtrados; isso não
  representa auditoria das dependências. A análise inicial dos testes também
  sinalizou macros de registro estático do Catch2 e concatenação em fixtures;
  a verificação final documentada cobre `libs/` e `apps/`.
- Instalação local, consulta de versão e validação da configuração instalada:
  aprovadas. Versão impressa: `ShadowNet 0.1.0`.
- Compose: schema/configuração validado com sucesso.

## Limitações da validação

- O Ninja local ficou parado na detecção ABI; o build validado usa
  `MinGW Makefiles`. O preset Ninja permanece para ambientes normais/CI.
- O GCC emitiu avisos em headers do Boost/MinGW (`-Wshadow`/`-Wconversion`);
  eles não foram tratados como aprovação de qualidade das dependências.
- O daemon Docker recusou acesso ao pipe: contêineres e imagem não foram
  construídos/executados nesta sessão. Somente `compose config` foi validado.
- A matriz CI foi escrita, mas seus resultados remotos não são presumidos.
- Linux, sanitizers e SIGTERM POSIX precisam de execução no ambiente apropriado.
- A API de exemplo ainda não participa de um E2E HTTP; isso depende do M3.
- Sem testes de TLS/certificados, reconexão, NAT/CGNAT ou desempenho de produção.
